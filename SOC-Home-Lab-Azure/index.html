SOC Home Lab 1

Written by: cyberNightKnight

-- Overview --

This lab consisted of setting up a honeypot in Azure and using the virtual machine's logs to build a map based on where the attackers' IP addresses were from. Additionally, I added an interface that showed the percentage of attacks from each region and an incident generation rule.

-- Steps --

  1. Create an Virtual Machine

    2. ** To do this, we first need to have an Azure account. In this case the account was created using a free subscription. **

    1. Create a Resource Group

      2. Resource Groups > +Create > Input the required data (used the location 2 of the Region) > Review + Create

    2. Create a Virtual Network (VNet)

      3. Virtual Networks > +Create > Add VNet name and nsure the Region is the same as the Resource Group > Review + create * We leave all other configurations as default for Security, IP addresses, and Tags, but it's useful to see how the VNet will be

    3. Create the VM

      4. > Virtual machines > +Create > Virtual machine > Add the Resource Group and name the VM * It's not recommended for the VM to be called in a similar way as the rest because the attackers might see it. So, I called it something similar to what a business would call it (ADMON-NET-WEST-2). Availability: No redundancy required > Security Type: Standard > Image: Windows 10 Enterprise, version 22H2 - x64 Gen2(free services eligible) > Size: Standard_D2s_v3

      Set username and password > Check licensing agreement

      Next > Disk: Standard HDD for lower cost

      Next > Network: Check Delete public IP and NC when VM is deleted

      Skip management config > Monitoring: Disable Boot diagnostics > Review + create

    4. Add NSG (firewall) rule to allow ANY traffic in Azure

      5. > Resource Groups > Resource that ends with 'nsg'

      For inbound rules, only the Remote Desktop Protocol is initially allowed

      > Delete inbound rule with 300 - RDP > Settings > Inbound security rules > +ADD > Change Destination Port to '*' (ANY) and name it > ADD

    5. Disable internal Windows firewall

      6. > Virtual machines > Click VM > In Windows App (computer app) > Add PC > Name: Public IP

      > wf.msc (Windows Defender) > Windows Defender Firewall Properties > Turn all firewall 'Profile' states Off > Apply > Ok

      > Ping the public IP

      Now the VM is open and reachable :)

      NOTE: If we try to access with wrong credentials, we can see those logs in Event Viewer>Security

  2. Forward logs to Azure
    1. Create Log analytics workspace

      2. > Log Analytics Workspaces > +Create > Fill in the required parameters

      > Microsoft Sentinel (SIEM) > +Create > Link to LAW

      ** Now the log workspace will be linked to the SIEM **

      To connect VM to LAW through Sentinel... In Sentinel > Content Management > Content Hub > Install Windows Security Events > Manage Windows Security Events > Check WSE via AMA (Azure Monitoring Agent) > Open Connector Page > Create data collection rule to forward the logs and grant them access to the SIEM > Resources: VM > Leave the next tabs as they are > Create *Simultaneously, we can see in the VM interface that the Connector is being installed

      To see logs:

      > In Logs Analytics Workspace > Logs > Tables > Search 'SecurityEvent'

      * Set to KQL mode

      * To only see certain parameters, use '| project {list of params}', or to only get a certain user, '| where Account == '{acount name}''

      *To search the location of an address: https://ipinfo.io/{ip address}

      IP address to country a. Upload .csv file with IP-location equivalences to Azure

      In Sentinel > Our Sentinel instance > Configuration > Watchlist...it will redirect to Defender. There, go to Microsoft Sentinel > Configuration > Watchlist > +New > Name & Alias: geoip > Source: Drop the file, Search key: network > Review + Create *To see watchlist from LAW, '_GetWatchlist("watchlist name")'

      In KQL (LAW), to search for the location of the IP : let GeoIPWatch = _GetWatchlist('geoip'); ''' let WindowsEvents = SecurityEvent | where IpAddress == '{ip address}' | where EventID == 4625 | order by TimeGenerated desc | evaluate ipv4_lookup(GeoIPWatch, IpAddress, network); WindowsEvents | project TimeGenerated, Computer, AttackerIp = IpAddress, cityname, countryname, latitude, longitude'''

  3. Create the map

    4. In Sentinel > Threat management > Workbooks > Add workbook > Edit > Remove all elements > Copy map.json from the description > Add query/Add data source + visualization > Advanced editor and paste the data > Done editing (at the top)

    Added percentages per country: (Pie chart) let GeoIPDB_FULL = _GetWatchlist("geoip"); let TotalEvents = toscalar( SecurityEvent | where EventID == 4625 | count ); SecurityEvent | where EventID == 4625 | evaluate ipv4_lookup(GeoIPDB_FULL, IpAddress, network) | summarize FailureCount = count() by countryname | extend Percentage = round(todouble(FailureCount) / todouble(TotalEvents) * 100, 2) | project country = tostring(countryname), Percentage | order by Percentage desc

  4. Generate incidents

    5. Sentinel > Configuration > Analytics > Create Scheduled Query Rule >
